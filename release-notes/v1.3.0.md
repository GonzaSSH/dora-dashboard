Every number now says what it means.

**A plain sentence on every tile**
- Built from the number, for example "A new release about every 9 days" or "4 of 10
  releases needed an urgent fix."
- Zero, one release and "not enough data" each have their own wording.

**Compared with the period before**
- Each tile compares the result with the previous period of the same length, for example
  "Faster than the previous 90 days (2.0 days vs 4.0 days)."
- If that period had fewer than 5 releases, the tile says so instead.
- Without a token, the comparison shares the 50-request allowance and never cuts the main
  numbers short; when it doesn't fit, the tile says a token is needed.

**DORA 2025 survey figures, where the measurement is direct**
- Deployment frequency and lead time show where the result sits among the teams DORA
  surveyed, for example "About 56% of surveyed teams have this lead time or shorter."
- The figures come from page 20 of DORA's *State of AI-assisted Software Development 2025*
  report, linked on the tile, used under its CC BY-NC-SA 4.0 licence.
- Each figure carries the note: "DORA surveys mostly teams running services. Libraries
  release on a different rhythm."
- The three estimated metrics show no benchmark, with one line on why.

**Saved examples**
- Both carry the comparison. The angular example is saved with a GitHub token so its
  comparison is complete, and the page says so.

**Tested by hand-worked values:** the test repository gained six earlier releases, and its
previous 90 days were worked out by hand before any code
([EXPECTED.md](https://github.com/GonzaSSH/dora-dashboard/blob/main/sandbox/EXPECTED.md)).
