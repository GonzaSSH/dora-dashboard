**Manual correction of failures**
- In the list of deployments, mark any release as failed or not failed. For a failure, pick
  the release that fixed it: the next one by default, any later one, or "not fixed in this
  period".
- All five numbers update straight away, with no GitHub requests. This works on the saved
  examples too.
- Corrected releases are labelled "manually corrected". A line above the tiles says how many
  releases were corrected, with a **Reset corrections** button.
- Failures that weren't fixed in the period count in the failure rate but not in recovery
  time, and the tile says how many there are.

**Shared links carry their definitions**
- Every setting you change and every correction is kept in the page address, and nowhere
  else. A shared link reproduces the same numbers.
- A **Definitions used** line under the tiles lists the rules behind the numbers, and marks
  the ones you changed.

**README**
- How to correct a release, in plain language.
- A new limitation: a repository with several applications is measured as one, while DORA
  is meant per application or service.
- A comparison with commercial tools, checked against their own documentation.
